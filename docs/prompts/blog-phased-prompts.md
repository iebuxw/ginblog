# Ginblog 分阶段实现提示词

> 每个阶段一个提示词，按顺序依次发给 Claude Code 执行。
> 每阶段遵循"先写计划确认，再动手"原则。

---

## 第一阶段：地基

```
帮我搭建一个 Go/Gin 博客系统（项目名 ginblog），技术栈：技术栈：Go1.18.9、Gin、GORM、Redis3、MySQL5.7、Nginx、Vue2、element-ui

第一阶段只做地基，不涉及文章/分类/标签等业务模块：

1. 项目骨架：标准目录结构（api/ model/ middleware/ routes/ config/ utils/）、go.mod 初始化
2. 配置加载：viper 读取 config.yaml、.env，支持数据库连接串、JWT 密钥、端口等配置项
3. 数据库：GORM 初始化 MySQL 连接，字符集 utf8mb4。但是数据库迁移不用 GORM，需要用 golang-migrate/migrate
4. 用户模块：用户模型（ID/用户名/密码/角色/创建时间）、注册接口、登录接口（返回 JWT）
5. 角色中间件：管理员/普通用户区分，路由级别权限控制
6. 公共中间件：跨域（CORS）、请求日志、异常恢复（Recovery）
7. 统一响应封装：成功/失败 JSON 格式统一，错误返回中文提示，不暴露原始 DB 错误
8. 时区：Asia/Shanghai（UTC+8）
9. 环境变量区分：开发环境(dev) / 正式环境(prod)
10. 全局异常：业务异常返回业务码 + 友好提示；系统 / 数据库底层异常 dev 返回堆栈 SQL，prod 对外隐藏底层信息，内部完整日志
11. 日志用 zap 库，不要用 gin 自带

约束：
- SQL 用参数绑定，禁止拼接
- 密码用 bcrypt 加密，禁止明文存储
- JWT 密钥从配置读取，禁止硬编码
- 先写实施计划（列出改动文件清单），确认后再动手
```

**验证标准**：Postman 能调通注册和登录接口，拿到有效 JWT token

## 第二阶段：核心 CRUD

```
在 ginblog 第一阶段基础上，新增文章、分类、标签三个核心业务模块。

1. 分类模块：分类模型（ID/名称/描述/创建时间）、CRUD 接口、名称查重
2. 标签模块：标签模型（ID/名称/创建时间）、CRUD 接口、名称查重
3. 文章模块：
   - 文章模型（ID/标题/内容/封面图/分类ID/状态/作者ID/创建时间/更新时间）
   - 文章-标签多对多关联表
   - CRUD 接口（创建时关联标签、编辑时同步更新标签关联）
   - 分页查询（支持按分类筛选、按标签筛选、按状态筛选）
4. 路由分组：
   - 公开组（/api/v1）：文章列表、文章详情、分类列表、标签列表
   - 鉴权组（/api/v1/admin）：所有写操作需 JWT + 管理员角色

约束：
- 创建/编辑前查重唯一性字段（分类名、标签名、文章标题），不依赖数据库唯一索引兜底
- 沿用第一阶段的目录结构和响应封装，不新增全局抽象
- 先列改动文件清单，确认后再动手
```

**验证标准**：用 JWT token 调通文章/分类/标签的增删改查及分页接口

## 第三阶段：能用了

```
在 ginblog 前两阶段基础上，新增评论、系统设置、后台管理前端和前台展示接口。

1. 评论模块：
   - 评论模型（ID/文章ID/父评论ID/用户名/邮箱/内容/状态/创建时间）
   - 评论 CRUD、支持嵌套回复
   - 后台审核接口（通过/拒绝）、删除接口
   - 前台：按文章获取评论列表（树形结构）

2. 系统设置模块：
   - 设置模型（ID/键/值/描述）
   - 接口可读写，支持批量更新
   - 预置字段：站点名称、站点描述、Logo URL、每页条数

3. 前台展示接口：
   - 文章列表（分页 + 分类筛选 + 标签筛选 + 关键词搜索）
   - 文章详情（含标签列表、评论列表）
   - 分类列表、标签云（带文章计数）

4. 后台管理前端（Vue 2 + Element UI，放在 web/ 目录）：
   - 登录页（调登录接口存 token）
   - 侧边栏导航：仪表盘、文章管理、分类管理、标签管理、评论管理、系统设置
   - 各模块：表格列表 + 新增/编辑弹窗 + 删除确认
   - 文章编辑页：Markdown 编辑器（mavon-editor 或类似）

约束：
- 沿用已有目录结构和响应格式
- 前端打包后通过 Go embed 嵌入或 nginx 反代
- 先列改动文件清单，确认后再动手
```

**验证标准**：浏览器能登录后台管理内容，前台接口返回正确数据

## 第四阶段：上线级

```
在 ginblog 前三阶段基础上，补齐部署和安全相关功能。

1. 图片/媒体管理：
   - 上传接口（限制文件类型和大小）
   - 文件存储（本地 static/ 目录或对象存储）
   - 文章内可引用上传的图片

2. 操作日志：
   - 日志模型（ID/用户ID/操作类型/操作内容/IP/创建时间）
   - 中间件自动记录关键操作（登录、增删改）
   - 后台可查看、按时间和操作类型筛选

3. 数据统计仪表盘：
   - 后台首页展示：文章总数、分类总数、标签总数、评论总数、近期注册用户数
   - 可选：近 7 天文章发布趋势图

4. Docker 部署：
   - Dockerfile（多阶段构建：编译 Go + 最终镜像）
   - docker-compose.yml（Go 服务 + MySQL + Nginx）
   - Nginx 配置：前端静态文件 + API 反代

5. 安全加固：
   - 接口限流（golang.org/x/time/rate 或中间件）
   - 密码强度校验
   - 敏感配置走环境变量（Docker 注入）
   - SQL 注入防护复查

约束：
- 不修改已有接口的请求/响应格式
- 迁移文件只新增不修改
- 先列改动文件清单，确认后再动手
```

**验证标准**：docker-compose up 一键启动，浏览器可完整使用博客系统
